# Correlated calendar list — local read-only integration

2026-09-10. Authorized bounded implementation; no approval, provider or deployment.

Decision: retain the frozen item/card, add a strict list parser and a scope-owned external store. The wire entry is exactly version personal-correlated-calendar-review-list-v1, workspaceId, readOnly:true, approvalAvailable:false, executionAuthorized:false, reviews (at most five unique review IDs), hasMore:boolean. All entries must pass the existing parser; any invalid item rejects the complete list. A valid empty response is not a 404 or failure. No hash or permission authentication is attributed to mobile parsing.

The existing owner personal-service screen gains a separate list beside legacy V1. A verified auth-user/session key must agree with the current bootstrap owner/workspace. Missing, refreshing or changed scope removes the child and its data. Each instance owns an abort controller and generation; reload, background, navigation blur and unmount clear data synchronously. Late results never refill a newer generation. Network cancellation is best effort, not evidence of a server rollback; reads perform no writes.

Only screen focus with active AppState, return to active foreground, or the explicit refresh button starts a read. There is no polling. One timer at the earliest display deadline clears the entire list without fetching. Each review's deadline is min(preparationExpiresAt, readStartedAt + (preparationExpiresAt - inspectedAt)); starting from the request beginning conservatively includes network latency. Thus a slow phone clock cannot extend the server-declared remaining window. Results and external-store snapshots also reject expired or backward/nonfinite local time. The expired snapshot is cached and cannot become fresh again without a new read. This is conservative local display freshness, never server authority. The server remains responsible for actual scope/current-authority/TTL. Clock skew can make mobile refuse an otherwise readable entry.

404 displays not-enabled/unavailable rather than empty success. Other errors remain opaque and offer explicit refresh. hasMore is a bounded-list notice, not a pagination control. No manual IDs, preparation, approval, POST, permission or write callback is added. UNKNOWN/synthetic wording and exact complete two-source text are preserved by the frozen card.

Shared MobileApi prerequisite: optional caller AbortSignal now propagates into its owned transport cancellation and an abort race including body decode; success/failure remove listeners. Existing callers without a signal keep their timeout/credentials behavior. New GET uses an explicit 15-second bounded deadline. Dedicated tests must cover pre-abort, fetch/body cancellation, own timeout, cleanup and legacy defaults before integration is considered stable.

Tests are local synthetic transport and React-render/controller tests; no Samsung/native foreground behavior, real provider or production activation is claimed.
