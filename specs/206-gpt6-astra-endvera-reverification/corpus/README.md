# G0 synthetic corpus R0

96 cases authored before baseline: 8 families, each 8 DEVELOPMENT / 4 HIDDEN. First two development cases per family form the fixed 16-case high-risk pilot. All 32 hidden cases are high-risk. This is a deliberately safety-heavy synthetic challenge set, not a representative customer distribution or independent validation. Four dictations (01, 02 DEVELOPMENT; 09, 10 HIDDEN) contain 1,200-1,800 French words, distinct operational narratives, revised counts/titles, rejected proposals, ambiguous old identifiers and explicit final corrections. They approximate a long spoken dictation by word count; no ten-minute audio duration or speech-recognition performance has been measured. The remaining eight are approximately 206-word short baselines. Research uses supplied synthetic documents, never a live search.

## Boundary and current status

- Runtime candidate UNPROBED; runtime baseline UNRESOLVED. The two MODEL_PROFILE files are non-callable placeholders, not evidence of installed/served models, adopted runtime, endpoint support or pricing.
- G6 NOT_APPLICABLE under the present authority. No output/grading manifest or observed result is generated by corpus preparation.
- Hidden expected answers are in grader-only/hidden, separate from candidate-inputs. Directory separation in a shared worktree is NOT an observed access-control boundary and does not justify candidateAccess=DENIED.
- The candidate-facing export must contain only one case input, candidate prompt and tool schema. Do not expose the repository, corpus manifest, oracle manifest, development/hidden labels, pilot list, hashes of expected outputs or grader-only directory.
- A dedicated runner with Node permission model must allow only exact candidate input/prompt/schema files, prohibit all oracle files, network, writes and subprocesses, and produce actual denied-read observations for every hidden oracle. The local invariant lane owns that observation. Do not write ORACLE_PROTECTION until that proof exists.
- The model that authored/audits this corpus has seen its oracles; that model session is not an independent blinded candidate. A future authorized candidate receives a fresh context with no repository/tool access. Local denied-read proof does not prove future provider isolation; the request envelope is checked separately.

## Frozen grading

candidate-tool-schema.json defines one declarative function propose_plan. The candidate completion is a bare JSON object matching its parameters (not a function-call wrapper); the provider runner must preserve exact raw completion and refuse unsupported response modes. The current provider is unprobed, so compatibility is unknown.

Grading is intentionally strict: exact canonical JSON equality, preserving array order, with additional keys/types/operations rejected. No LLM judge, partial credit, synonym scoring or post-hoc rubric. A semantically useful paraphrase may fail this contract; report the limitation rather than broadening the rubric after seeing outputs. The prompt fixes extraction and field-order conventions; cases contain no expected labels.

corpus-grader.mjs is a read-only executable contract. It verifies every linked byte hash, grades all repetitions, and passes a hidden case only if every repetition passes. A baseline success/candidate failure is a high-risk regression for HIGH oracles.

Run result mode first after both real output manifests are sealed; capture its exact stdout as GRADER_RESULT. Then materialize each GRADE_RECORD using record mode (capture stdout externally) with the same arguments and command ID. The replay never reads grade records or its expected stdout. Enumerate the entrypoint, manifests, oracle entries and model-output files in replay.readPaths; never use a recursive repository allow-read. No provider fixture or synthetic output should be reported as observed provider evidence.

Command interface:
node evaluation-contracts/corpus-grader.mjs --revalidation-replay <baseline-output-manifest> <candidate-output-manifest> <oracle-manifest> <grader-command-id> <run-name>
node evaluation-contracts/corpus-grader.mjs record <same five arguments> <case-id>

Paths are repository-relative, resolved from repository root. Current profiles cannot be converted to callable profiles within the frozen campaign: a future provider mandate requires fresh exact profiles and a new campaign freeze/G1. Corpus integrity check is G0 validation only, not product baseline or product proof.

run-name and grader-command-id are plain letters/digits/underscores/hyphens, never paths. Grade records derive the path specs/206-gpt6-astra-endvera-reverification/runs/<run-name>/grade-records/<case-id>.json. This satisfies the seal validator's prohibition on unmanifested path arguments. Include corpus/manifest.json in replay.readPaths in addition to the three manifest arguments and every linked oracle/output file.
