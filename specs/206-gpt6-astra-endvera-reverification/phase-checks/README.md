# Frozen G1/G7 execution contract

G0 prepares this kit; do not execute product baselines until CAMPAIGN_HEAD is committed. Do not edit these files after the freeze. Commands execute from the isolated repository root. The parent recorder consumes the exact `command` string in commands.json and records campaignId, observedHead/Tree, timestamps, real exit code, stdout and stderr in distinct files. The runner's markers follow substantive assertions; they are never status arguments.

For every command create the canonical PHASE_CHECK_OBSERVATION. Then invoke the existing `evaluation-contracts/phase-check.mjs --revalidation-replay <PHASE_CHECK_CONTRACTS.json> <observation>` as a separate PHASE_CHECK command, with only those inputs and the two observed streams in readPaths. Add the entrypoint itself to replay readPaths as required by the canonical validator. The JSON result is the wrapper's native stdout. `parserSha256` hashes UTF-8 JSON.stringify({stdoutAll,stderrNone,notApplicableStdoutAll}); the schema-conforming contracts file and frozen helper files also receive artifact hashes in the parent manifest.

## Scope and honest limitations

- ROOT_BUILD runs typecheck, lint, provider boundary, release manifest, store compliance and Webpack build; it runs all components and fails if any fails. MOBILE_BUILD runs typecheck, lint, installed Expo Doctor and all-platform export offline. An offline-doctor error is a failure, not a fabricated green.
- Unit/integration checks parse the actual Vitest JSON report, require successful assertions, zero failed tests/suites and exact selector presence. Full root/mobile floors are 2400/195 passed tests; no-tests cannot pass. Focused frozen tests add a spring-forward nonexistent-time refusal, ordinary DST offset, malformed envelope and instruction-injection boundary.
- WEBHOOK_FORGERY covers the local simulator's invalid-signature admission boundary, not cryptographic verification of a live provider webhook. OUTCOME_UNKNOWN covers the mobile persisted outbox fixture, not a real interrupted provider delivery. Critical route smoke starts a real local production web process and verifies health, public pages and anonymous authentication refusals; no authenticated customer journey is claimed.
- PostgreSQL uses the pre-existing @prisma/dev 0.25.2 runtime directly, backed by PGlite; this is **not native multiprocess PostgreSQL**. Each check allocates a new UUID-named stateful server, fresh loopback ports and a disposable database. No existing application/Prisma server is used. Only its original default connection creates the disposable database; all SQL migration/seed/test workers use the guarded disposable URL. Migrations run through the repository SQL splitter, not Prisma migrate deploy, because this local pooled engine does not support the migration engine's prepared-statement semantics. This limitation remains explicit.
- MIGRATION_UPGRADE starts from the full migration chain immediately preceding the latest committed migration, inserts a synthetic sentinel, applies the latest migration and reads it back. It is a **reconstructed previous-chain snapshot**, not a production backup or independent attestation that this is the business-supported upgrade baseline. Its exact previous migration is printed in output. Parent must not relabel this as an observed customer-data upgrade.
- SYNTHETIC_SEED creates one explicit `@example.invalid` user and a synthetic persistence marker; it does not invoke the development seed that requires admin credentials. Restart closes the owned server, starts it again against the same unique state directory, and reads both records through a fresh process. Owned servers always close in finally. Synthetic disk stores are deliberately retained for forensic recovery, not recursively deleted by this runner; no existing store is removed.
- NATIVE_CRASH_REPRODUCTION inventories only `specs/206-gpt6-astra-endvera-reverification/evidence/device/`. A filed crash/logcat/tombstone/ANR artifact makes it fail pending reproduction. An empty signal inventory can yield NOT_APPLICABLE with the explicit limited reason in its contract. This is not evidence that the app is crash-free, nor evidence of Samsung installation or observation. Place all G4 native crash signals in this folder before G7.
- SECRET_SCAN reads tracked text files, reports counts/paths only and detects private-key, OpenAI/Anthropic/OpenRouter, GitHub and AWS key forms. A flagged synthetic credential fixture remains a flagged match until reviewed; no generic fixture allowlist hides it. Raw bytes are never echoed by that scan. Parent's seal-wide scan remains separately required.
- The local network preload rejects non-loopback Node socket/DNS/fetch calls and propagates to child Node processes. The environment is allowlisted, npm is offline, telemetry is disabled and worktree .env files are refused. This is a cooperative local execution guard, not a native firewall or adversarial sandbox; native binaries still require the credential-free local mandate.
- BACKLOG_VALIDATION validates IDs, statuses, dependencies, cycles and terminal release against the product backlog. QUEUE_VALIDATION calls the canonical Brain validator read-only. Parent must freeze/hash that external validator as supporting G0 provenance; this runner does not edit Brain.

G0 validation: `node specs/206-gpt6-astra-endvera-reverification/phase-checks/validate-kit.mjs`, Node syntax checks, and the canonical phase-check adversarial fixture. Those validate the kit, not product baseline outcomes.
