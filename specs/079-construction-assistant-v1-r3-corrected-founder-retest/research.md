# Research: Construction Assistant V1 R3 Corrected Founder Retest

## Decisions

1. **One integrated product screen** — R2 failed partly because the founder had to coordinate a guide, several pages and technical identifiers. R3 owns the sequence and context.
2. **No comparative control** — R3 answers only whether the corrected loop works clearly in Olivier's hands. Any ChatGPT comparison would require an equal, timed human run and is excluded.
3. **Database-backed evidence** — UI success text is insufficient. Every automatic metric is recomputed from PostgreSQL records or the exact closed service return.
4. **Server-owned replay identity** — one generated provider identifier is stored server-side and reused for the duplicate. It is never founder input.
5. **Temporary local surface** — the console exists only with an explicit development-mode flag and is removed before final product closure.
6. **Single-use human observation** — dry runs use a technical mode that cannot write founder completion. Once Olivier starts, product files are frozen and the sealed outcome is final for R3.

## Alternatives rejected

- Reusing the R2 external guide: rejected because it reproduces the choreography failure.
- Browser-only mocked success: rejected because it cannot prove PostgreSQL truth.
- Auth bypass for convenience: rejected because test routes are still untrusted endpoints.
- Persisting the console as a production feature: rejected because R3 is an experiment, not a product authorization.
