# Local populated70 →79 rehearsal

This is an explicit mode of the existing approved native harness, not a new
launcher, remote upgrader, backup tool or application seed. No PostgreSQL run is
authorized merely by these files existing. Controller review and a coordinated
native slot precede execution.

Approved invocation shape (absolute installed PowerShell and approved runtime):

```text
node specs/210-personal-live-activation/check-local.mjs postgres-native <absolute-pwsh.exe> <approved-RuntimeRoot> --migration-rehearsal
```

The switch cannot be combined with a test filename. Without the switch the
ordinary migrated-template/per-file suite is unchanged; this folder does not add
a file to its twenty-test-file glob.

## Recorded phases

1. Existing binary hashes, private cluster ACL, ignored path, loopback SCRAM,
   environment allowlist and real two-backend probe.
2. Exact catalog79 staging, schema and two private Prisma configs. Actual
   installed Prisma6.19.3 applies prefix70; it creates its own migration history.
3. Fixed SQL seed creates fourteen synthetic legacy rows across ten tables.
   Revoked accounts have no credentials or grants. Money, requests, prior result,
   lease, Unicode and timestamps are sentinels, not provider evidence. No audio
   is created. No historical provider acceptedAt is invented.
4. Whole-row/history snapshot and baseline checks; seal populated70 with no
   remaining connections, then clone it. Both databases remain available in the
   retained cluster for later authorized diagnosis.
5. Actual Prisma applies71–79 to the clone. Complete old rows and first70 history
   must remain unchanged. Only specified new NULL/default columns are accepted.
   New proof tables must be empty. UTC defaults, complete77 function body,
   selected required schema guards and global invalid/disabled guards are checked.
6. Verification receipt and existing bounded graceful shutdown. Overall outer
   receipt must report exit0 AND confirmed shutdown; an earlier verifier success
   does not override shutdown failure.

The rehearsal has one600s stage budget, before its first migration, with remaining
time supplied to each child. Existing bounded process cleanup and server shutdown
allowances remain separate. Every executable input is reinspected before its
phase, including exact migration-directory inventories; expected-file hashing
alone is insufficient. The cluster ACL and trusted local operator are still the
boundary: this is not protection from concurrent hostile writes by that same
Windows identity between verification and consumption.

The existing workspace dependency chain is narrowly recognized as
r03/node_modules → r9-mobile-assistant/node_modules → r8-mobile-foundation/node_modules.
The resolved package and its ancestors must be regular, Prisma must be6.19.3,
and all source/staged paths still reject links. No dependency is modified.

## Evidence limits

Pure comparator/static tests are not SQL execution. A passing real rehearsal is
synthetic populated PostgreSQL17.11, not managed PostgreSQL18, restored customer
data, production workload, full schema-drift certification, live provider flow or
deployment authorization. Initial migration checksums are exact staged local
bytes; separate documented LF-only differences against remote history are not
silently normalized here.

No migration, baseline or fixture is automatically repaired after failure. Retain
the first failing receipt and all private clusters. Do not reset, drop, alter
applied SQL, fabricate Prisma history, run application seed, regenerate clients,
change node_modules or reuse this as a remote executor.
